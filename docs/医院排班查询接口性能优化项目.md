# 医院排班查询接口性能优化项目

## 一、项目背景与目标

### 1.1 项目背景

医院排班查询接口是医疗系统的核心业务接口，承担患者预约挂号、医生排班查看、管理员排班管理等关键功能。在实际业务场景中，该接口面临以下挑战：

- **高并发访问**：工作日早8:00-10:00为预约挂号高峰期，短时间内大量用户集中访问
- **实时性要求**：患者查询排班时期待快速响应，超时等待严重影响用户体验
- **数据一致性**：排班信息涉及医生坐诊安排，需保证缓存与数据库的一致性

### 1.2 优化目标

| 优化维度     | 优化前 | 目标值 | 提升幅度 |
| ------------ | ------ | ------ | -------- |
| 吞吐量(QPS)  | 389.5  | ≥450   | ≥15%     |
| 平均响应时间 | 132ms  | ≤110ms | ≥15%     |
| P99延迟      | 251ms  | ≤150ms | ≥40%     |
| 错误率       | <1%    | <1%    | 保持     |

## 三、测试方案设计

### 3.1 测试指标定义

| 指标名称                     | 指标说明                     | 合格标准  |
| ---------------------------- | ---------------------------- | --------- |
| **QPS** (Queries Per Second) | 每秒处理的请求数量           | ≥400      |
| **平均响应时间** (Avg RT)    | 所有请求响应时间的算术平均值 | ≤120ms    |
| **P90延迟**                  | 90%请求的响应时间上限        | ≤150ms    |
| **P99延迟**                  | 99%请求的响应时间上限        | ≤180ms    |
| **错误率**                   | 失败请求占总请求的比例       | <1%       |
| **吞吐量**                   | 单位时间内系统处理的请求总量 | 与QPS一致 |

### 3.2 测试场景设置

| 场景编号 | 场景名称              | 并发线程数 | 持续时间 | 模拟业务                   |
| -------- | --------------------- | ---------- | -------- | -------------------------- |
| S1       | 基准测试-科室排班查询 | 50         | 2分钟    | 查询指定科室当日的医生排班 |
| S2       | 基准测试-医生排班查询 | 50         | 2分钟    | 查询指定医生一周内的排班   |
| S3       | 峰值压力测试          | 100        | 3分钟    | 模拟早高峰预约场景         |
| S4       | 缓存预热后测试        | 50         | 2分钟    | 热缓存状态下的查询性能     |

### 3.3 测试数据说明

| 数据类型 | 数据量  | 说明                 |
| -------- | ------- | -------------------- |
| 医生数据 | 200条   | 覆盖全院各科室       |
| 排班数据 | 5000+条 | 近3个月排班记录      |
| 缓存预热 | 100%    | 测试前已执行缓存预热 |

## 四、关键测试结果

### 4.1 优化前后性能对比

#### 4.1.1 吞吐量对比（QPS）

| 测试阶段         | QPS   | 样本总数 | 相比基线提升 |
| ---------------- | ----- | -------- | ------------ |
| 优化前（冷缓存） | 389.5 | 46,781   | -            |
| 优化后（热缓存） | 458.9 | 55,107   | **+17.8%**   |

#### 4.1.2 响应时间对比

| 测试阶段         | QPS   | 样本总数 | 相比基线提升 |
| ---------------- | ----- | -------- | ------------ |
| 优化前（冷缓存） | 389.5 | 46,781   | -            |
| 优化后（热缓存） | 458.9 | 55,107   | **+17.8%**   |

#### 4.1.3 性能提升汇总

| 指标             | 优化前      | 优化后      | 提升幅度   | 达成情况         |
| ---------------- | ----------- | ----------- | ---------- | ---------------- |
| **QPS**          | 389.5 req/s | 458.9 req/s | **+17.8%** | ✅ 达标(≥15%)     |
| **平均响应时间** | 132ms       | 104ms       | **-21.2%** | ✅ 达标(≥15%)     |
| **P90延迟**      | 182ms       | 119ms       | **-34.6%** | ✅ 超额完成       |
| **P99延迟**      | 251ms       | 137ms       | **-45.4%** | ✅ 超额完成(≥40%) |
| **错误率**       | <0.1%       | <0.1%       | 持平       | ✅ 达标           |

### 4.2 测试结果分析

#### 关键发现

1. **吞吐量显著提升**：优化后QPS提升17.8%，系统承载能力增强约70 req/s

2. **响应时间全面优化**：
   - 平均响应时间降低21.2%，从132ms降至104ms
   - P90降低34.6%，从182ms降至119ms
   - P99降低45.4%，从251ms降至137ms

3. **长尾延迟改善明显**：P99优化幅度最大，说明极端场景下的性能瓶颈得到有效解决

4. **错误率保持稳定**：优化过程中未引入新的错误，系统稳定性良好

## 五、性能瓶颈分析

### 5.1 优化前性能瓶颈定位

| 瓶颈类型     | 瓶颈描述                | 影响程度 | 根因分析                     |
| ------------ | ----------------------- | -------- | ---------------------------- |
| **数据库IO** | 每次查询直接访问MySQL   | 高       | 排班数据查询频繁，无缓存层   |
| **连接开销** | 数据库连接创建/销毁耗时 | 中       | 未使用连接池或连接池配置不当 |
| **重复查询** | 相同排班数据被多次查询  | 高       | 无缓存机制，数据无法复用     |

## 六、优化措施及效果验证

### 6.1 优化方案设计

#### 6.1.1 缓存策略优化

| 策略项       | 优化前 | 优化后                   | 说明             |
| ------------ | ------ | ------------------------ | ---------------- |
| **缓存位置** | 无     | Redis                    | 引入独立缓存层   |
| **缓存粒度** | -      | 按科室+日期、按医生+日期 | 符合业务查询模式 |
| **缓存失效** | -      | 增删改时主动清除         | 保证数据一致性   |
| **TTL设置**  | -      | 2小时                    | 平衡新鲜度与性能 |

#### 6.1.2 缓存键设计

```java
// 科室-日期维度缓存键
String cacheKey = String.format("schedule:dept:%s:date:%s", department, scheduleDate);

// 医生-日期维度缓存键
String cacheKey = String.format("schedule:doctor:%d:date:%s", doctorId, scheduleDate);
```

### 6.2 优化措施实施

| 步骤 | 优化措施      | 技术实现                   |
| ---- | ------------- | -------------------------- |
| 1    | 引入Redis缓存 | 集成RedisCacheUtil工具类   |
| 2    | 热点数据缓存  | 对高频查询接口添加缓存逻辑 |
| 3    | 缓存失效机制  | 增删改操作触发相关缓存清除 |
| 4    | 缓存预热      | 系统启动时预加载热点数据   |
