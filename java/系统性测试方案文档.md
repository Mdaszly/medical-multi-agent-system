## 一、测试目标

本测试方案旨在验证医疗多Agent系统各功能模块的正确性、稳定性和性能，确保系统能够满足业务需求和质量标准。

### 1.1 测试覆盖范围

| 层级 | 模块 | 测试重点 |
|------|------|----------|
| P0 | 知识图谱核心服务 | Neo4j数据查询、症状-疾病-ICD关联 |
| P1 | AI桥接与多Agent | 症状抽取、图谱查询、ICD验证 |
| P2 | 工具与校验功能 | MedicalTools、IcdGroundingValidator |

## 二、API接口测试

### 2.1 测试环境配置

| 环境变量 | 值 | 说明 |
|---------|-----|------|
| baseUrl | http://localhost:8080 | 服务地址 |
| POSTGRES_HOST | localhost | 数据库地址 |
| NEO4J_URI | bolt://localhost:7687 | Neo4j地址 |

### 2.2 核心API测试用例

#### 2.2.1 POST /api/knowledge-graph/sync-to-rdb

**功能描述**：验证Neo4j到PostgreSQL的数据同步功能

| 测试场景 | 请求 | 预期响应 | 断言规则 |
|---------|------|---------|---------|
| 正常场景 | 空请求体 | `{"syncedRelations": N, "message": "同步完成"}` | HTTP=200, syncedRelations>=0 |
| Neo4j为空 | 空请求体 | `{"syncedRelations": 0, "message": "同步完成"}` | HTTP=200, syncedRelations=0 |

#### 2.2.2 GET /api/knowledge-graph/symptoms/suggest

**功能描述**：测试症状名称联想功能

| 测试场景 | 请求参数 | 预期响应 | 断言规则 |
|---------|---------|---------|---------|
| 正常场景 | `prefix=头`, `limit=5` | `["头痛", "头晕", ...]` | HTTP=200, 列表非空 |
| 边界条件 | `prefix=""` | `[]` | HTTP=200, 空列表 |
| 模糊匹配 | `prefix=热` | 包含"发热"等 | HTTP=200, 包含相关症状 |

#### 2.2.3 GET /api/knowledge-graph/diagnosis/{symptomName}

**功能描述**：查询症状对应的疾病和ICD编码

| 测试场景 | 请求 | 预期响应 | 断言规则 |
|---------|------|---------|---------|
| 正常场景 | `/diagnosis/头痛` | 包含疾病和ICD信息 | HTTP=200, totalCount>0 |
| 不存在症状 | `/diagnosis/未知症状` | 空结果 | HTTP=200, totalCount=0 |

## 三、服务层功能测试

### 3.1 KnowledgeGraphService测试用例

| 测试方法 | 测试场景 | 预期结果 |
|---------|---------|---------|
| `findSymptomDiagnosesRows` | 有效症状名 | 返回非空列表，包含ICD编码 |
| `findSymptomDiagnosesRows` | 空症状名 | 返回空列表 |
| `findSymptomDiagnosesFuzzy` | 有效关键词 | 返回模糊匹配结果 |
| `suggestSymptomNames` | 有效前缀 | 返回联想列表 |
| `lookupByIcdCode` | 有效ICD编码 | 返回对应诊断信息 |
| `exportAllSymptomIcdRelations` | 正常数据 | 返回所有症状-ICD关系 |
| `isEmptyGraph` | 空图谱 | 返回true |
| `isEmptyGraph` | 非空图谱 | 返回false |

### 3.2 SymptomIcdSyncService测试用例

| 测试方法 | 测试场景 | 预期结果 |
|---------|---------|---------|
| `syncFromNeo4j` | Neo4j为空 | 返回0，不执行插入 |
| `syncFromNeo4j` | 新数据 | 正确插入ICD、症状、关系表 |
| `syncFromNeo4j` | 已存在数据 | 更新优先级，不重复插入 |
| `syncFromNeo4j` | ICD为空 | 跳过该行，继续处理 |

### 3.3 KnowledgeGraphBootstrap测试用例

| 测试场景 | 配置条件 | 预期结果 |
|---------|---------|---------|
| 空库自动导入 | `bootstrap-on-startup=true` | 自动导入10个症状及ICD数据 |
| 启动时同步RDB | `sync-to-rdb-on-startup=true` | 启动时执行数据同步 |
| 禁用自动导入 | `bootstrap-on-startup=false` | 不执行自动导入 |

## 八、端到端测试

### 8.1 完整流程测试

**场景1：初诊问诊流程**

```
用户输入 → 症状抽取 → 图谱查询 → ICD验证 → 诊断输出
```

| 步骤 | 输入 | 预期输出 |
|-----|------|---------|
| 1. 用户输入 | "我最近经常头痛" | 进入问诊流程 |
| 2. 症状抽取 | 提取"头痛" | 正确识别症状 |
| 3. 图谱查询 | 查询头痛相关疾病 | 返回偏头痛等疾病 |
| 4. ICD验证 | 验证ICD编码 | 返回VERIFIED状态 |
| 5. 诊断输出 | 生成诊断报告 | 包含ICD编码和建议 |

**场景2：复诊问诊流程**

```
历史记录 → 上下文恢复 → 增量查询 → 诊断更新
```

### 8.2 异常场景测试

| 场景 | 测试步骤 | 预期结果 |
|-----|---------|---------|
| 图谱服务不可用 | 关闭Neo4j后请求 | 系统降级，使用RDB数据 |
| 空输入 | 提交空表单 | 返回错误提示 |
| 网络超时 | 模拟网络延迟 | 超时处理，友好提示 |
