## 二、详细测试场景

### E2E-001: 初诊问诊完整流程

**业务描述**：患者首次进入问诊系统，输入症状描述，系统进行症状识别、图谱查询、ICD验证，最终生成诊断建议

**测试步骤**：

| 步骤 | 操作 | 预期结果 | 验证点 |
|-----|------|---------|-------|
| 1 | 用户进入问诊首页 | 页面正常加载，显示症状输入框 | 页面渲染 |
| 2 | 输入症状："我最近经常头痛" | 症状输入成功 | 输入验证 |
| 3 | 点击"开始问诊" | 进入问诊流程 | 流程跳转 |
| 4 | 系统识别症状 | 提取"头痛"症状 | 症状抽取 |
| 5 | 图谱查询 | 返回头痛相关疾病和ICD编码 | 图谱查询 |
| 6 | ICD验证 | groundingStatus=VERIFIED | ICD验证 |
| 7 | 生成诊断报告 | 包含疾病名称、ICD编码、建议科室 | 诊断输出 |
| 8 | 查看Agent Trace | 显示工具调用记录 | 可观测性 |

**预期输出数据**：

```json
{
  "conclusion": "根据您的症状，可能的诊断为偏头痛",
  "icd_references": [
    { "code": "G43.909", "disease": "偏头痛，未特指" }
  ],
  "recommended_department": "神经内科",
  "risk_level": "低风险",
  "groundingStatus": "VERIFIED",
  "graphEvidence": [...]
}
```

### E2E-002: 复诊问诊流程

**业务描述**：患者再次进入问诊，系统恢复历史上下文，进行增量查询和诊断更新

**测试步骤**：

| 步骤 | 操作 | 预期结果 | 验证点 |
|-----|------|---------|-------|
| 1 | 用户登录系统 | 成功登录，显示历史问诊记录 | 登录验证 |
| 2 | 选择历史问诊记录 | 加载历史上下文 | 上下文恢复 |
| 3 | 补充新症状："头痛加重，伴有恶心" | 新增症状成功 | 增量输入 |
| 4 | 点击"继续问诊" | 系统进行增量分析 | 增量查询 |
| 5 | 查看更新后的诊断 | 诊断结果更新，包含新症状信息 | 诊断更新 |

**预期输出数据**：

```json
{
  "conclusion": "您的头痛症状有所加重，建议尽快就医",
  "previous_diagnosis": "偏头痛",
  "updated_fields": ["severity"],
  "groundingStatus": "VERIFIED"
}
```

### E2E-003: 症状联想与选择

**业务描述**：用户在输入症状时，系统提供症状名称联想建议

**测试步骤**：

| 步骤 | 操作 | 预期结果 | 验证点 |
|-----|------|---------|-------|
| 1 | 在症状输入框输入"头" | 下拉显示匹配的症状列表 | 联想功能 |
| 2 | 从下拉列表选择"头痛" | 症状自动填充到输入框 | 选择功能 |
| 3 | 输入"未知症状" | 无匹配结果，提示"未找到匹配症状" | 边界处理 |
| 4 | 清空输入框 | 联想列表消失 | UI交互 |

**预期输出数据**：

```json
{
  "suggestions": ["头痛", "头晕", "头皮瘙痒", "头颈痛", "头部外伤"],
  "matchedCount": 5
}
```

### E2E-004: ICD编码验证流程

**业务描述**：验证ICD grounding机制是否正确工作，防止LLM幻觉

**测试场景1：ICD在白名单中**

| 步骤 | 操作 | 预期结果 |
|-----|------|---------|
| 1 | 输入症状"头痛" | 系统识别症状 |
| 2 | 图谱查询 | 返回候选ICD: G43.909 |
| 3 | LLM生成诊断 | 使用ICD: G43.909 |
| 4 | ICD验证 | groundingStatus=VERIFIED |

**测试场景2：ICD不在白名单中**

| 步骤 | 操作 | 预期结果 |
|-----|------|---------|
| 1 | 输入症状"头痛" | 系统识别症状 |
| 2 | 图谱查询 | 返回候选ICD: G43.909 |
| 3 | LLM生成诊断 | 使用ICD: Z99.999（虚构编码） |
| 4 | ICD验证 | groundingStatus=WARNING |
| 5 | 系统提示 | 显示警告："检测到未验证的ICD编码" |

### E2E-005: 数据同步验证

**业务描述**：验证Neo4j到PostgreSQL的数据同步功能

**测试步骤**：

| 步骤 | 操作 | 预期结果 | 验证点 |
|-----|------|---------|-------|
| 1 | 确保Neo4j中有测试数据 | 包含症状、疾病、ICD节点 | 数据准备 |
| 2 | 调用同步接口 | 返回同步成功 | API调用 |
| 3 | 查询PostgreSQL | icd10_code表有数据 | ICD表同步 |
| 4 | 查询PostgreSQL | symptom表有数据 | 症状表同步 |
| 5 | 查询PostgreSQL | symptom_icd_rel表有数据 | 关系表同步 |
| 6 | 验证数据一致性 | Neo4j与PostgreSQL数据一致 | 数据一致性 |

**验证SQL**：

```sql
-- 验证ICD表
SELECT COUNT(*) FROM icd10_code;

-- 验证症状表
SELECT COUNT(*) FROM symptom;

-- 验证关系表
SELECT COUNT(*) FROM symptom_icd_rel;
```

| 步骤 | 操作 | 预期结果 |

| 1 | 输入空症状 | 系统提示"请输入症状描述" |
| 2 | 点击提交 | 不发起请求，显示错误提示 |

#### 场景C：网络超时

| 步骤 | 操作 | 预期结果 |
|-----|------|---------|
| 1 | 模拟网络延迟 | 响应时间超过超时阈值 |
| 2 | 系统处理 | 显示友好的超时提示 |
| 3 | 日志记录 | 记录超时错误 |
